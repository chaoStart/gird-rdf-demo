# 配电网本体模型构建与知识推理

来源：用户分享对话 https://chatgpt.com/share/6b03a0e4-69d8-83e9-9bda-b05914e675e4 中涉及的《配电网本体模型构建与知识推理.md》，与上传的《配电网本体模型构建与知识推理(1).md》正文一致。仅整理格式及标点。

## 场景

配网/调度：构建配电网领域本体模型，使 AI 能回答“馈线停电影响哪些用户”“配变过载应切换到哪条备用线路”等推理性问题。

## 背景

公司在建电力知识库，需要配电网本体作为骨架。本体不是数据库表——它定义了领域的概念（类）、关系、推理规则。数据库只能告诉你“配变 A 挂在馈线 X 下”；本体能让 AI 推理出“馈线 X 的 S1 断开 → S1 下游配变 A/B/C 失电 → 影响 1200 户 → 应合上联络开关 L1 将负荷转到馈线 Y”。

## 任务要求

1. 本体模型设计（核心）：用 OWL/RDFS/YAML 定义——
   - 类（Class）：至少 15 个核心类（变电站、馈线、分段开关、联络开关、配变、线路段、用户、故障、检修工单等），含继承关系。
   - 属性（Property）：每个类的数据属性和对象属性（如供电关系、上下游关系）。
   - 推理规则（Axiom）：至少 8 条，含故障传播规则（上级断 → 下游失电）、过载触发规则、负荷转移可行性判定规则。
2. 推理验证：设计 5 个推理问题（如“S1 断开后哪些用户失电”），给出预期答案，验证你的本体能否支持推理。
3. 本体可视化：核心类和关系图（任何工具）。
4. 设计文档（800 字）：本体与数据库的本质区别、你的设计取舍、本体如何支持推理。
5. Demo 系统：本体可视化、Agent 对话推理。
